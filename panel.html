⚠ Importante para OBM M2 fuente remota
En Settings → Remote Proxy Sources la URL de la fuente debe llevar el filtro; si no, OBM descarga todas las líneas (cientos de miles, muertos incluidos) y se queda parsesando y checkeando proxies:
  • Mal: http://127.0.0.1:8082 → devuelve el pool entero.
  • Bien: http://127.0.0.1:8081/proxy.txt?alive=1&sort=ping&max=300 → solo los 300 vivos más rápidos (con Pattern ([0-9]+\.[0-9]+\.[0-9]+\.[0-9]+:[0-9]+) y Output [1]).
uTLS · TLS v13 MASTER + OBM motor externo Copiar
El TLS_v13_MASTER no es un proxy: habla x-tls-url y usa un motor Go (uTLS: chrome_131, firefox_120, safari_ios…). El gateway puede delegarle las peticiones http:// (modo uTLS) y el motor sale por este mismo pool:
  • Arranca el gateway con --tls-engine http://127.0.0.1:9150 --tls-engine-key HVN-...
  • Las peticiones https:// (CONNECT de OBM) siguen yendo por el pool normal: para aplicar uTLS ahi haria falta terminar el TLS aqui (y activar Ignorar errores de certificado en OB).
--tls-engine http://127.0.0.1:9150 --tls-engine-key HVN-... --tls-engine-profile chrome_131
sin probar en esta sesión
⚠ Aviso de seguridad LAN
El launcher del TLS_v13 expone su API en 0.0.0.0: cualquiera de tu red puede usar tu motor uTLS y tu licencia. El motor Go (9150) sí es local. Fix: bloquea el puerto en el firewall de Windows.
